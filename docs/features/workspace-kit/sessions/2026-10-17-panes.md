# Chat and context panes

## Context

This is the third of five workspace-stack cycles
([cycle](../../../cycles/2026-10-panes.md),
[port shape §2b](../../../items/workspace-stack-port-shape/write-up.md#2b-the-cycles)).
The wiki layer had landed earlier the same day, so the flagged Scriptorium
(`SCRIPTORIUM_KIT=1`) matched the shipped one at the CLI but had no surface.
Cole approved the cycle and its six new items in a Scriptorium review session
(2026-10-17). The branch was `cycle/panes`. As in earlier cycles, every item was
built by a subagent in its own worktree, checked by a verifier with no stake in
it, and cherry-picked.

## What Happened

**The port base moved before the work started.** A read of Story Studio with
`git show` and `git log` only found:

- **Chat:** every commit since `027d7a3` was one we wanted (the floating
  composer `5db9315`, notes with the agent `85a319e`, `ae08f10`, via/refs
  `bbc54fd`). So chat was ported whole from `develop` (`2c4b6c2`).
- **Context:** taken from `027d7a3` plus six commits, leaving out Story Studio's
  three copy-in commits (`6b3d943`, `7afe5d9`, `83ea109`). Their one-project
  workspace copies files in; ours edits them where they live.
- **The plugin host:** touches neither pane.

**The items, in the order they ran:**

1. **`kit-port-chat` and `kit-port-context`**, in parallel.
   - Both are byte-faithful apart from listed translations: one MIME rename,
     ward rewording, and one test harness adaptation.
   - The context verifier diffed it both ways: `027d7a3` plus the six commits,
     and `develop` minus the copy-in commits. Both were identical.
   - Cole reworded one checklist line mid-cycle. "No context code copies a file
     anywhere" became "nothing is copied except a file the human drops onto a
     set or folder they chose". The first wording also ruled out the drop import
     that the shipped Scriptorium has always had.
2. **`kit-pre-move-confirm-slot`.**
   - An app may answer before any move with a confirm, a refusal, or nothing.
   - Scriptorium fills it from `move.plan`.
   - **Cole ruled the fallback:** when the check fails or times out, keep "Move
     anyway", but name what was not checked: links, and whether the file leaves
     a git repository. The shipped surface refuses instead.
3. **`kit-chat-about-chip`.**
   - A message now stores an app's `about` parts, and the chip labels them in
     the app's words.
   - `entryIds` was retired: nothing produced it, and refs cover its use.
   - It took two verification rounds (Discoveries).
4. **`scriptorium-kit-interim-frame`.** The flagged Scriptorium's first surface:
   context, chat, Notes and Tasks around a centre that says the document pane
   comes next. It is checked in a real browser.
5. **`scriptorium-kit-ask-location`.** Cole's "ask where, last location
   preselected" rule (from `scriptorium-no-default-workspace`), built as a
   generic `askLocation` slot.
6. **`message-via-and-refs`** closed: both halves are now in both kits.

## Notable Discoveries

- **Storing more makes a bad value cost more.** Storing app `about` parts moved
  a hook's output ahead of `addMessage`. Then the first verifier found that a
  BigInt or a cycle broke every later write, and the session with it. The second
  found that a result which throws when read lost the human's whole message, and
  that long part names got past the size caps. Both were fixed, each with tests.
  The pattern: when a value moves from "sent once" to "stored", rerun the
  hostile-input probes, because the cost of a bad value changes.
- **A gate claimed green can be stale.** The frame's implementer reported a
  green gate that had run before its new `index.html` was committed. The
  gate-honesty ward counts committed files only, so the next run went red. A
  verifier caught it, since verifiers run the gate on the committed tip.
- **Wards can overclaim too.** A spawn-path ward comment said the frame folder
  was pinned, but the ward only reads paths with an extension. And the dist
  roster's flat walk saw `dist/kit` as a file and warned on every clean run.
  Both are now real cells, and planted regressions turn them red.
- **Copy-in is not drop import.** The first wording of a checklist line also
  ruled out a behaviour the shipped app has always had. The verifier's job of
  naming exactly what a drop does settled it.
- **Agent worktrees break the gate in the main checkout** (the nested
  `biome.json`), as the memory notes. The combined gate ran on explicit paths
  while agents were live, and in full once they were removed.
