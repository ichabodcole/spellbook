# 4.0.0 — the breaking changes, enumerated

**This file exists for the same reason `3.0.0-breaking-changes.md` does.** The
work since 3.1.0 moved all nine spell CLIs onto one shared command table and
fixed a batch of bounty and astrolabe defects. Every one of those commits was
typed `feat` or `fix` with no `!` and no `BREAKING CHANGE:` footer, so
release-please would have cut **3.2.0** — a minor — for a release in which
invocations that exited 0 now exit 2, a tail that waited forever now gives up,
and two outputs change shape.

⚠ **EVERY ENTRY BELOW WAS OBSERVED, NOT COPIED.** A draft release note carried a
list of breaking changes. Each claim was re-run against the shipped 3.1.0 build
(tag `spellbook-v3.1.0`, its committed `dist/`) and against `develop`, through
the same launcher (`bun plugins/spellbook/skills/<spell>/scripts/cli.ts …`), in
a throwaway `HOME`, `TMPDIR` and `<SPELL>_HOME`. The population was every
invocation in the CLI golden corpus (`grimoire/fixtures/cli-golden/`, 881
records) plus targeted runs for what the corpus cannot reach: a live bounty
board, a live imago session, a stub astrolabe daemon that never goes down, and
bounded tails. Some draft claims did not survive (see the end). Enumerated at
the release commit: **fifteen breaking changes** — two exit codes, eight refused
invocations, four output shapes, one timing change. Where a count and a list
disagree, trust the list.

## How failures look now

Every spell CLI fails the same way, defined in `src/kit/wire/errors.ts`:
**stdout is empty, and stderr carries one JSON document on one line**:

```text
{"ok":false,"error":{"kind":"usage","exit_code":2,"retryable":false,"message":"…","hint":"…","choices":["…"]},"meta":{"command":"update"}}
```

| Exit | `kind`      | Meaning (from `EXIT_FOR`)                          |
| ---- | ----------- | -------------------------------------------------- |
| 2    | `usage`     | the caller can fix this by changing the command    |
| 1    | `internal`  | the spell broke; the invocation may have been fine |
| 5    | `not_found` | the named thing does not exist                     |
| 6    | `conflict`  | a precondition failed                              |

`hint`, `choices` and `server` (the daemon's own reply, verbatim) appear only
when set; `retryable` is always `false`. `meta.command` names the verb, or is
`null` when the command line was rejected before a verb was known. Route on
`kind`, the exit code and `choices` — **never on `message`**, whose wording
changed across the roster in this release. Two exits live outside that module:
`0` is success, and `124` is the idle timeout on spells that take a positive
`--timeout`. A line on stderr starting `# warning:` is not a failure: stdout and
the exit code are unchanged.

## Exit codes

A script branching on a number is the thing most likely to break.

1. **bounty `tail --session <id>` for a board that never existed: 0 → 5.**
   Before: one `tail.closed` line on **stdout** at once, exit 0, offering
   `open --restore <id>`. Now: a retry line per attempt on stderr naming the id
   and its source, then a `not_found` envelope on **stderr**, exit **5**, after
   about 8 seconds (a 5-second retry window), stdout empty. A board that existed
   here and closed still ends `tail.closed`, exit 0. Why: "closed" was a false
   report for a board that was never there, and the restore it offered could not
   work.
2. **astrolabe `close` on a daemon still answering after 3 s: 0 → 1.** Before:
   `{"ok":true,"applied":true,…}` on stdout at once, exit 0, while the daemon
   was still up. Now: it waits up to 3 s for the daemon to go down, then fails
   with `internal`, exit **1**, on stderr ("close was acknowledged but the
   daemon was still answering after 3s"). Why: a read right after `close` could
   see a board that was about to vanish; `ok` now means it is gone.

## Refused invocations

Each of these is now a `usage` refusal — exit **2**, envelope on stderr, nothing
written — where it used to be accepted.

3. **A bare `bounty` or `imago` is a usage error.** Before: help text on stdout,
   exit 0. Now: exit 2, the verbs in `choices`. Why: a success exit for a
   command that did nothing is the shape an agent cannot detect (3.0.0 made the
   same change on grapevine, magpie and glamour).
4. **A flag that belongs to another verb is refused** on bounty, astrolabe and
   imago. `bounty list --status x`, `astrolabe state --clear`,
   `astrolabe list --as x` and `imago sessions --session s1`: 0 → 2.
   `imago state --clear`: 5 (no session) → 2. The envelope's `choices` is the
   verb's own flag set. Why: the flag was silently ignored, so the caller
   believed it had an effect.
5. **An extra positional is refused, not dropped.** `astrolabe remove p1 extra`
   (against a daemon) and `astrolabe state -- --x`: 0 → 2.
   `bounty update t1 --status doing -- --session-key K` on a live board: 0 → 2
   (it applied the update and dropped the token; with no board it was 5).
   `magpie close extra`, `magpie state extra`, `imago select a off x`,
   `mind-mapper read m1 m2` and `mind-mapper projects x`: 5 (no session) → 2.
   Why: the dropped token was usually a flag the caller meant, and the write
   went ahead without it.
6. **`version` and `help` given a flag are refused.** `version --bogus` and
   `version --help` on glamour, scriptorium, astrolabe and mind-mapper, and
   `--version --junk` on glamour and scriptorium: 0 → 2. astrolabe
   `help --bogus` and `help --help`: 0 → 2. Why: every verb now accepts only its
   own flags, and these take none.
7. **imago `handoff` needs exactly one of `<text…>` or `--clear`.** On a live
   session, a bare `handoff` (which silently cleared the handoff) and
   `handoff --clear hello` (which ignored the text): 0 → 2. Why: the silent
   clear was indistinguishable from raising one.
8. **bounty `update` refuses values that would blank a field.** On a live board,
   each of these was `{"ok":true}` at exit 0 and is now 2: `--title ""`,
   `--notes ""`, `--stdin` with empty stdin, and `--stdin` together with
   `--title` (stdin used to win, unwarned). Each message names the recovery;
   `--clear-notes` is the new way to clear notes on purpose. Why:
   `update --stdin` destroyed a live card's title (`s5-9`).
9. **bounty `add` and `update` refuse an unknown `--status`.** On a live board,
   `add second --status bogus` created the card as `todo` and
   `update t1 --status bogus` answered `noop`, both exit 0; now exit 2 with
   `todo`, `doing`, `review`, `done` as `choices`, and nothing is written. Why:
   the status was dropped silently while the caller thought it was set.
10. **mind-mapper checks the command before looking for the daemon.** With no
    daemon, `zone create` (no name) and `doc kind D1 note --clear` exited 5
    `not_found`; now 2, because a missing name and `--clear` with a kind are
    wrong whatever the daemon's state. Why: a 5 told the caller to open a
    daemon, when re-running would have failed on the command itself.

## Output shape

11. **imago `sessions` prints JSON.** Before: one prose line per session
    (`imago-… 0 batches · 0 generations — imago`), or `no saved sessions`. Now:
    one document, `{"sessions":[{id, title, batches, generations, updatedAt}]}`,
    newest first (`{"sessions":[]}` when empty). `--human` keeps the old prose.
    Why: every other imago verb prints JSON.
12. **astrolabe `close` with nothing to close drops its `error` key.** Before:
    `{"ok":true,"applied":false,"error":"no daemon running"}`. Now:
    `{"ok":true,"applied":false,"outcome":"already-closed"}`. Both exit 0. Why:
    an `error` key on a successful no-op read as a failure to anything checking
    for one.
13. **digestify's command-line rejections carry `meta.command: null`.** An
    unknown flag, a flag missing its value or a stray argument used to say
    `"command":"review"`; failures after parsing still do. Why: the rejection
    now comes from the shared parser, before the review starts.
14. **`choices` on a rejection changed.** It is now the rejected verb's own flag
    set rather than the whole flag table (bounty `tail`'s went from 23 flags to
    7); a flag before the verb (`imago --session s1 say hi`, still exit 2) lists
    the root flags `--help --version -h -V` instead of the verbs; grapevine
    drops `choices` from a flag given without its value; digestify's
    unknown-flag `choices` gain `--help`, `--version`, `-h` and `-V`; and every
    verb list gains `version` and `schema`. Why: `choices` is part of the
    contract, and it now says what that position would actually accept.

## Timing and behaviour

15. **bounty `tail --session-key <key>` that never resolves gives up.** Before:
    it retried forever (still running when stopped at 25 s), with
    `# no session yet, retrying…` on stderr. Now: each retry line names the id
    it derived and from what (key + cwd), and after about 8 seconds it exits
    **5** `not_found` with a hint. A tail with no named target (no `--session`
    or `--session-key` on the command line) still waits, as before. Why: a key
    derived in the wrong directory looked like a quiet board, forever (issue
    #98).

## Not breaking, and worth saying so

- **Newly accepted, previously refused (2 → 0):** `version` (and `--version` /
  `-V` where it had none) on bounty, imago, magpie and digestify; `schema` on
  astrolabe, bounty, digestify, imago, magpie and mind-mapper; digestify
  `--help` / `-h` / `help`; imago `sessions --human`; bounty
  `update --clear-notes`; mind-mapper `doc -- delete` now reads the doc named
  "delete" (was 2). Nothing could have depended on these failing.
- **Additive fields:** bounty `update`'s success envelope gains `fields`.
- **`# warning:` lines on stderr** when `--` turns an accepted flag into text
  (seen on astrolabe `status p1 -- --phase x`, grapevine `who -- --all`, bounty
  `add -- text --session-key k`). Exit code and stdout are unchanged.
- **Message wording** changed everywhere (`unknown command "x"`, arity messages
  naming the missing `<positional>` in place of `usage: …` lines). Same exit,
  same `kind`; `message` was never the contract.

## Claimed, and not observed

- **imago `tail` passes the tail client's exit code through instead of
  always 0.** True of the code, not observable: SIGINT and SIGTERM on a live
  tail, a tail on an unknown `--session`, and `--since 3 --once` all exit 0 on
  both builds, and every stop path in `src/kit/wire/tailEvents.ts` returns 0
  today. Not listed as a break.
- **"A flag before the verb is refused"** (imago, mind-mapper): it already was,
  at exit 2 `usage`; only `choices` moved (entry 14).
- **grapevine's misplaced flag and `-- -- --zz`**: exit 2 `usage` on both
  builds; only the wording moved.
- **bounty's named tail gives up "after about 5 seconds"**: the retry window is
  5 s, the observed wall time about 8 s, which is what SKILL.md says.

## Not verified

- The live-daemon form of entries 5 and 10 on magpie, imago and mind-mapper
  (`magpie close extra` against a running session, where 3.1.0 presumably closed
  at 0; `doc kind D1 note --clear` against a running mind-mapper, where it
  presumably cleared). Observed only with no session: 5 → 2.
- astrolabe `close`'s wait on a daemon that does go down (entry 2 was observed
  only against a stub that never does).
