# 6.0.0 — upgrading from 5.2.0

Scriptorium was rebuilt on a new shared core, and that changed its command line,
its output and how it stores a session. The other spells kept every verb and
flag they had and gained `help <verb>`; three behaviours changed for every spell
or for grapevine, listed under "Every spell" below. Each entry below was
observed by running the same commands on the 5.2.0 build (tag
`spellbook-v5.2.0`) and on the 6.0.0 build, each in a throwaway home, and by
comparing the two builds' `schema` output.

Two Scriptorium words used below: a **set** is a folder the session shows as one
unit in its sidebar, and the **context** is everything the session shows there
(sets and single documents). `state` lists both.

## Bun 1.4.0 or later

6.0.0 needs Bun 1.4.0 or later on your PATH; 5.2.0 named no version. Spellbook
is built and tested on 1.4.0. Nothing checks the version when a spell starts, so
an older Bun is not refused, only untested.

## ⚠ Don't open a converted session with 5.2.0

6.0.0 converts a session saved by 5.2.0 the first time it restores it (see
below). After that, don't open it with 5.2.0 again. If you do, 5.2.0 opens it
but sets its workspace to your home folder, so an `import` without `--into`, or
a `new-doc` in the workspace, lands in your home folder. Once 5.2.0 writes
anything to it (a version, a note, a task, a chat line), 6.0.0 refuses to
restore it: `conflict`, exit 6, "was not written by scriptorium: its manifest
has Scriptorium's shape".

The only recovery is the copy 6.0.0 kept at the first conversion. In the
session's folder (`$SCRIPTORIUM_HOME/sessions/<id>/`, by default
`~/.scriptorium/sessions/<id>/`), move `manifest.json` aside and copy
`manifest.pre-migrate.json` to `manifest.json`; 6.0.0 then converts and restores
it again. You lose every version, note, task and chat line made since that first
conversion, in either build. Their version files stay in the session's `docs/`
folder, but the session no longer lists them. Your own documents are not
affected: Scriptorium edits them where they are.

## Sessions saved by 5.2.0 restore

`open --restore <id>` brings back a session saved by 5.2.0, with its versions
and their labels, notes, tasks and chat. It is converted the first time it is
restored: the old manifest stays beside the new one as
`manifest.pre-migrate.json`, and the chat says it was converted. The 5.2.0
workspace folder becomes a set, unless a set already shows it.

## Scriptorium: removed verbs and flags

Each of these now fails as `usage`, exit 2. The exit codes still mean what they
meant in 5.2.0 (2 usage, 1 internal, 5 not found, 6 conflict). The replacements
answer in a different shape, so they are not drop-in swaps; `help <verb>` gives
each one.

| 5.2.0                      | 6.0.0                                                                                                                                        |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `dangling [--entry <set>]` | `link-check`, which checks the whole session in sections; its `dangling` section lists each link with `source`, `line`, `raw` and `set`      |
| `workspace [dir]`          | None: there is no workspace (see below)                                                                                                      |
| `graph --entry <set>`      | `graph --within <folder>`, or `graph --focus <doc>`. The nodes and edges carry different fields                                              |
| `backlinks <path>`         | `backlinks --doc <path>`, which answers `backlinks` (each with `source`, `line`, `raw`) where 5.2.0 answered `target`, `related` and `links` |

**With no workspace, a new file goes where you name it.** In 5.2.0, `import`
without `--into` put the copy in the workspace, and `new-doc` and `new-folder`
took a folder in a set or the workspace folder. Now `import` needs
`--into <folder>`, and `new-doc` and `new-folder` need a path inside a set or a
folder in one; anything else is refused. To make a place, use the verbs
`add-folder <path>`, `make-set <doc>` or `add <folder>`.

## Scriptorium: changed behaviour on verbs that stayed

| Verb                                           | 5.2.0                         | 6.0.0                                                         |
| ---------------------------------------------- | ----------------------------- | ------------------------------------------------------------- |
| `open` with no paths                           | an empty session              | the current folder is added as a set                          |
| `note-edit` on a note the human wrote          | rewrote it                    | `conflict`, exit 6: use `note-reply`, which keeps their words |
| `task-remove` on a running task                | removed it                    | `conflict`, exit 6: `task-cancel` it first                    |
| `version-new` with text piped in, no `--stdin` | ignored the text, made a copy | `usage`, exit 2: pass `--stdin` or `--body-file`              |
| `task`                                         | `{task, text}`                | `{task, title, status: "running", message_id}`                |
| `task-status <id> <text>`                      | `status` was your text        | `status` stays `running`; your text is `detail`               |

## Scriptorium: changed output

**Everywhere:** every `ts`, `createdAt` and other time, in `state` and on the
tail, is an ISO 8601 string, where it was milliseconds. Some tail events no
longer carry a `ts` at all: see below.

**`state`:**

- Chat messages: `who` became `from`, and they gain `type`. A human message's
  `selection` and `activePath` became `about` (`doc`, `version`, `path`, and the
  lines and text when they selected some), and it gains `via`.
- Versions: `author` became `by`, and `from` became `fromVersion`.
- Notes: `who` became `by`.
- Tasks: `text` became `title`, and `who` became `by`. `status` changed meaning:
  it was free text set by `task-status`; it is now one of `open`, `running`,
  `done`, `failed` or `cancelled`, with the free text in `detail`.
- `docMeta` moved to `appState.docMeta`. `docs[].meta` is gone (the verb
  `meta <path>` gives a document's frontmatter). `workspace` and `home` are
  gone.

**`tail`:**

- A human `message`: `selection` and `active` became `about`, and it gains `via`
  and `hint`.
- `version.created`: the human's was already this event; `from` became
  `fromVersion`, and it gains `label` and `path`. The agent's was a `system`
  event with `fact: "version.created"`; it is now this event too, with no `ts`.
- `merged`, and the agent's `note.added`, `note.resolved` and `task.done`, were
  `system` events with that name in `fact`; each is now its own event type (the
  human's `note.added`, `note.resolved` and `task.done` already were).
  `note.resolved` gains `resolved`; `task.done` gains `title` and `outcome`.
  None of these four carries a `ts` any more.
- The human's `note.edited` event is gone: a note edit, by either side, is a
  `system` event with `fact: "note.edited"` and no `ts`. The human's edit
  carries `lines`, `quote`, `body` and `hint` instead of `text`; the agent's
  carries only `doc`, `note` and `by`.
- Task events carry `title`, where they had `text`. New task events arrive too:
  `task.created`, `task.progress`, `task.failed` and `task.cancelled`.
- `doc.opened` is no longer on the default tail; pass `--all` to get it.

Scriptorium's `SKILL.md` and `help` describe the full shape.

## Every spell: changed behaviour

- **A page reached under another host name is refused.** Each spell's local
  server now answers `403` to a request whose `Host` is not `127.0.0.1:<port>`,
  `localhost:<port>`, or the address given to `--host`. It closes a
  DNS-rebinding hole. If you reached a spell through another name (an
  `/etc/hosts` alias, a proxy), start it with `--host` set to that name, or use
  `127.0.0.1`.
- **`<verb> --help` is help now.** It used to be a usage error (exit 2); it now
  prints the verb's usage and exits 0, like `help <verb>`.
- **grapevine `stop`, `restart` and `roll` refuse a daemon that won't exit.**
  They used to report success after their 5-second wait even if the daemon still
  answered. They now fail: `internal`, exit 1, with the daemon's pid in the
  message so you can kill it.

## mind-mapper's code left the plugin

5.2.0 shipped no `SKILL.md` for mind-mapper, so it was never installed as a
spell. Its CLI, server and built `dist/` were in
`plugins/spellbook/skills/mind-mapper/`, though, and 6.0.0 no longer ships them:
they moved to `plugins/unreleased/` until its app is finished. Anything that ran
`plugins/spellbook/skills/mind-mapper/scripts/cli.ts` directly will not find it.
