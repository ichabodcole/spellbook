# 3.0.0 — the breaking changes, enumerated

**This file exists because the version number nearly lied.** The release that
became 3.0.0 was originally cut as **2.3.0**: not one of its 521 commits carried
a `!` or a `BREAKING CHANGE:` footer, which is the only thing release-please
reads, so the generated changelog had `### Features` and `### Bug Fixes` and no
breaking-changes section at all — while earlier releases in the same file _do_
have one, making its absence read as a positive signal that there were none.

⚠ **THE COUNT BELOW IS DERIVED, AND AN EARLIER ONE WAS NOT.** Drafts of the
release note said "twelve breaking changes", a figure counted at an earlier
commit and carried forward without being re-derived. Enumerated here at the
release commit: **fifteen wire-and-exit-code changes**, plus **one removed human
affordance**. Where a count and a list disagree, trust the list.

The fullest account of the release is the merge commit body —
`git log --first-parent main`.

## Exit codes

A script branching on a number is the thing most likely to break.

1. **"No session" moved from exit 2 to exit 5** on **glamour, imago and
   bounty**, joining magpie and mind-mapper, which had already moved. A script
   testing `exit == 2` for that case is now wrong on five spells.
2. **bounty's cooperative refusals moved off exit 1**, which under the house
   taxonomy means _the spell broke_. Before: prose on stderr, a legacy
   `{"ok":false,"applied":false,…}` on **stdout**, exit 1. Now: stdout empty,
   one envelope on stderr, `applied:false` inside `error.server`.
   - duplicate `--id` on `add` → **6** `conflict`
   - `claim` a task someone else owns → **6** `conflict`
   - `block` forming a cycle → **6** `conflict`
   - `block --on <ghost>`, and `update` / `remove` / `unblock` on a ghost id →
     **5** `not_found`
   - `init` / `close` refused by the daemon → **6**, or the daemon's own kind
   - ⚠ One deliberate exception survives: `bounty open`'s attach refusal keeps
     exit 2 **and** keeps printing the live board's discovery JSON on stdout.
     Recognise it by `restoreSkipped.requested`.
3. **grapevine `pull` on a missing channel: 2 → 5.**
4. **grapevine `send` to an archived channel: 2 → 6.**
5. **mind-mapper's exit codes moved** — needs-project and the 409 family 2 → 6;
   unknown entity → 5.
6. **A bare invocation is a usage error (exit 2), where it previously exited 0**
   — on grapevine, magpie and glamour. A success exit for a command that did
   nothing is the shape an agent cannot detect, so this is a correctness fix
   that happens to break anything relying on it. `help` / `--help` remain the
   help path at exit 0.

## Behaviour a caller depended on

7. **grapevine: a read verb no longer creates a channel.** `pull`, `read`,
   `wait`, `triage` and a bare `topic <name>` now **404** on a channel that does
   not exist. They used to silently rebuild a channel a human had just closed —
   empty, file-less, back in `list`, answering `{"ok":true,"messages":[]}`
   forever with no way to discover why. `open`, `tail`, `watch`, `send`,
   `announce`, `mark` and `topic <name> <text>` still create: only an act
   declaring intent does. **Breaking if you read before you open, and it fails
   loudly the first time.**
8. **`--timeout 0` reversed meaning** on magpie and bounty. It used to exit 124
   on the first tick (magpie) or close an unwatched board (bounty), both
   accidents of a `>=`. A non-positive `--timeout` now means the daemon
   **never** idle-closes.
9. **magpie's `--timeout` changed meaning inside its documented range** — from
   "the longest this daemon may sit idle while connected" to "linger this long
   after the last subscriber leaves". An agent holding a tail on a quiet session
   used to be killed at the 30-minute mark. ⛔ Neither magpie's nor bounty's
   `SKILL.md` documents what `--timeout 0` means, before or after.
10. **Unknown flags are rejected** rather than accepted and ignored, and **flags
    are scoped to their verb.** On grapevine all 26 flags previously parsed on
    every verb. A recognised flag on the wrong verb is refused as MISPLACED,
    with that verb's flags as `choices`.

## The event stream

11. **mind-mapper's event cursor field is `id`, not `seq`** — on the wire and in
    every JSONL line `tail` writes into an agent's pipe.
12. **mind-mapper's keepalive comment is `: hb`, not `: keepalive`.**
13. **SSE streams open with a `: connected` comment** on astrolabe, magpie,
    glamour and bounty, so a quiet stream flushes headers and leaves no
    `fetch()` unresolved. A client reading **line 0** rather than the first
    frame breaks; every house tail client drops `:` lines.
14. **bounty's `connected` / `disconnected` presence frames left the replay
    log.** They are live-only and **no longer carry an `id`**. A tail at
    `--since 0` used to replay the whole browser-presence history, each frame
    advancing the agent's cursor.
15. **imago's `proposal.send` / `proposal.dismiss` no longer put the proposal id
    in the frame's `id` field** — that field is the tail cursor, so
    `ev.id > since` compared a string and those frames were never replayed at
    all. The cursor is the cursor now; the proposal rides beside it as
    **`proposalId`**, on the wire, in the shipped types and in the SKILL.

## One human affordance

16. **grapevine's watch surface no longer has a per-row 🗑 button.** Closing a
    channel is reached through a right-click context menu on the rail row,
    alongside Edit topic and Archive / Unarchive. Deliberate — the menu is the
    one path — but old muscle memory will not find the button.

## Not breaking, and worth saying so

Every spell daemon now **refuses a request carrying a foreign `Origin`** (403).
This closes a demonstrated attack — any web page you were browsing could open a
WebSocket to `127.0.0.1` and drive a spell — and it is **not** a breaking change
for any legitimate caller: a CLI sends no `Origin` at all, and a spell's own
page sends its own. If something of yours breaks on this, it was reaching a
daemon from a browser page the daemon did not serve.
