# The kit split's guard (G1) — 2026-11-24

Part of [Split the kit](../../../cycles/2026-12-kit-split.md), step G1 of
[feature/kit-split](../../../features/kit-split/feature.md).

## Context

The guard every later step works under: a file-size limit that fails a file
growing past it, a tier test that fails a part importing upward, and a test that
the CLI and daemon still start without the heavy modules.

## What Happened

- **The limit.** `style/noExcessiveLinesPerFile` at 1,200 for
  `src/**/*.{ts,tsx}`, tests left out, with one override per file over it. Biome
  found exactly the write-up's 15, none new and none under. Four had grown since
  the 2026-11-17 baseline: `session.ts` 7,848 (was 7,816), `verbs.ts` 1,937
  (1,855), `DocumentPane.tsx` 2,115 (2,104), `protocol.ts` 1,565 (1,561). Each
  override is the file's exact count, so one more line fails. `biome.json` takes
  no comments, so the reasoning is in the playbook and the commit.
- **The tier test.** `tests/architecture/session-tiers.test.ts` and a cut-down
  `walk.ts`, from Story Studio's develop at `b2abead4`, with empty tables until
  S2; its fixtures run against a copy of Story Studio's table. Their rule
  against importing the kit by package name is dropped: our kit has no package
  name.
- **The start-path test** replaces `noteGuard.lazy.test.ts`'s first test: the
  CLI entry loads no `workspace/session.ts`, `workspace/server.ts`, micromark or
  mdast; the daemon entry loads no projection or mdast until `loadNoteGuard`;
  the daemon's third-party packages are exactly 28 (micromark's family and
  `yaml`).
- **Docs.** `docs/playbooks/splitting-a-module-playbook.md` (the ownership rule,
  Story Studio's rules 19 and 20, a verification list);
  `docs/architecture/workspace-session.md`, a port of theirs adapted to the
  state before any part is built, with the parts we have and they don't; one
  line in `AGENTS.md`. Story Studio's `session.members.test.ts` was not ported
  (not in the spec); the page says so.

Rebased onto develop after G0 and the grapevine fix landed; `test-timings.json`
was regenerated on the new base rather than merged.
