# Bun 1.4.4 — 2026-11-17

Part of
[Research first, and the bugs that bite](../../../cycles/2026-11-research-and-safety.md).

## Context

Cole moved his machine to Bun 1.4.4 and asked for the pin to follow. Both pins
moved together (`.bun-version` and the `bun` devDependency), with the lockfile.

## What Happened

The first gate under 1.4.4 failed 169 tests. 166 were one cause: our WebSocket
test harness read `state` straight after connecting, and 1.4.4 resolves `onopen`
before the daemon's first frame arrives. The harness now waits for the first
state frame. The other two were real behaviour changes: `Bun.Image` now decodes
a truncated JPEG, PNG or GIF, and `fetch` gives a 204 a null body.

The first image fix refused any decodable file whose tail lacked the end marker.
The review caught that this also refused whole GIFs with trailing bytes, which
the drop route stores as they came. An implementer replaced the tail guess with
a walk of each format's structure (PNG chunks, JPEG segments then the entropy
scan, GIF blocks), and reworded the refusal, which had said the file "does not
decode".

Story Studio is already on 1.4.4 and has the same `imageDecodes` and `cutShort`;
kit-parity message 68 told them; they hit all three and landed their fix
(message 69), with the decode dropped and only the tail guess kept, so message
70 sent the structure walk and the whole-GIF trap. They also found that 1.4.4
decodes a CMYK JPEG; nothing here relied on it not decoding.

## Notable Discoveries

- A Bun upgrade can loosen a decoder. "It decodes" stopped meaning "it is
  whole", and only a test of a cut file that still decodes would notice.
- The 204 change made a branch the old test called unreachable the live one.

## Review

Census from the Agent tool's roster of available types:
`feature-dev:code-reviewer` was rejected (it lists BashOutput and KillShell but
not Bash); `general-purpose` (`*`) and `doc-reviewer` ("All tools") have shell
access. `general-purpose` was chosen for a code branch.

First pass: ran the gate (exit 0), `git grep` across the callers, and probes of
`cutShort`/`imageDecodes` on built files. Verdict: with fixes. It found the
whole-GIF-with-trailing-bytes refusal, the stale refusal wording, and that the
zero-byte `stream-end` backoff had lost its test. All three were fixed.

Second pass: re-ran the gate (6,449 pass) and its probes, built JPEG and GIF
edge cases by hand (restart markers, DNL, fill bytes, a COM holding FF D9, no
global colour table, zero-length sub-blocks) and every cut of each, ran
`cutShort` over about 10,000 real images on the machine (none refused), timed a
64 MB worst case (linear), and confirmed in a scratch clone that the new tests
fail on the old code and on a backoff mutant. Verdict: ready to merge.

## Follow-up

The remaining behaviour change: a whole JPEG or GIF written without its end
marker is refused even when it decodes. Rare; noted, not filed.
