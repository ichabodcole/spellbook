## Review

Dual review, both general-purpose (shell access; `feature-dev:code-reviewer`
rejected for having none, `code-simplifier` for editing code), each in its own
copy.

- **Regular — Yes.** An AST comparison of the eight members, with and without
  comments: identical under the listed substitutions, so call order is identical
  by construction. Own-write records, `lastActiveText` and the outside flags
  stay single-instance. Fixed from it: S7 and S8 prose still called reconcile
  not built; the header misdescribed `shownBundleOf`; and the S9 section gave a
  reason ("FSEvents reports real paths") the code does not state, now removed.
- **Adversarial — Yes.** A deterministic differential harness, 200 seeds × 200
  steps over every reconcile entry point and the outside writes that drive it
  (identical repeats, renumbered versions, symlinked originals, bundles, the
  echo window): results, document records, files on disk and the call log
  identical at all 40,000 steps. **The flake:** `daemon.integration.test.ts` run
  interleaved, develop and branch alike, sequential and four at a time under
  load: 0 failures in 46 runs on each side. Recorded as load. Of 44 planted
  faults the tests missed 21, the harness caught 16 of them; filed as
  `session-reconcile-test-gaps`. The worst: a file that comes back with other
  text no longer marked changed, so Save could overwrite it without asking.
