## What Happened

- **`Chats`** (`session/chats.ts`, 51 lines, tier 2) owns `m.chat`:
  `addMessage`, `messages`. Ours is one chat, so the part is small.
- **`Tasks`** (`session/tasks.ts`, 129 lines, tier 3) owns `m.tasks`:
  `createTask`, `task`, `transitionTask`, `setTaskDetail`, `removeTask`,
  `clearFinishedTasks`, `tasks`. All moved now, not split with S7: the verbs
  need only `core.m` and tier 0. `restore`'s pass that fails or cancels the
  daemon's tasks stays in the facade's static `restore`.
- **Persisting through the facade.** Each part takes a `persist` hook,
  `() => this.persist()`, rather than calling `core.persist`, because
  `manifest.test.ts` replaces the facade's `persist` to count writes; calling
  `core` directly fails that test. Every persist sits where it did.
- **Names.** The facade's field for the part is `taskList`: `tasks()` is a
  public method. The daemon's `TaskEngine` is `src/kit/workspace/tasks.ts`,
  outside `session/`; no part imports it, and the tier test refuses one that
  does.
- **The override** is 6,700 (was 6,768). The tier test gains `chats: 2` and
  `tasks: 3`, its only change. The architecture page gains a section for the two
  parts. The gate's build rebuilt the scriptorium server bundle.
