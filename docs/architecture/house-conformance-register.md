## How a row closes

**Closed with a sha**, where the close is a commit. A2 (`5c56eab`), B6
(`ec543bfb`), C5 (`0260c725`), C8 and C10 (both `826294a2`).

⚠ **Or closed with a DATE AND A D-NUMBER, where the close is a RULING or a
correction rather than a commit.** A10, B7 and F3 all close this way, and the
header used to say _"nothing is closed here without a sha"_, which those three
rows falsified. **Amended rather than enforced** (D93): a ruling that a row's
premise was wrong, or that the answer is KEEP, has no commit to point at, and
demanding one would either fabricate a sha or leave a settled row open. The
requirement is unchanged in substance — **a row never closes on an assertion**;
it closes on a commit, or on a ruling a reader can go and read.

⛔ **A row is struck through, never deleted.** A2 is kept visibly stale-then-
closed on purpose, as the first proof that this is a living document rather than
a list someone tidies.

## The rule for fix-now versus defer

**Fix now** when any of these is true:

1. **This branch created it.** A port that breaks something owns it. (imago's
   dropped `proposalId`, bounty's silent-on-pass ARM 1b.)
2. **It makes a shipped document, type or comment LIE.** A false claim is worse
   than a missing one, because a reader stops looking. (`shared/types.ts`
   declaring a field the daemon no longer sends; a SKILL section teaching the
   pre-port exit codes.)
3. **It is an instrument that guards the ports still to come.** Repairing a
   guard inside the port it guards means fixing it while a 1,700-line relocation
   competes for attention. (The spawn-path ward's blindness; the
   launcher-pairing ward.)
4. **Leaving it makes the NEXT port pay the same cost.** Playbook gaps, always.
5. **It is one line and its absence would mislead.** Rename a ward cell whose
   title no longer matches what it asserts.

**Defer to this register** when any of these is true:

1. **It is pre-existing and this branch did not change it.** (bounty's
   four-entry watchdog gap predates the port — though see below: it moved to
   fix-now because the CODE claimed otherwise.)
2. **The fix requires a decision that spans spells.** One spell cannot choose
   the house's `hint`/`choices` convention alone.
3. **It would change caller-visible behaviour beyond the port's contract.** A
   port's contract is "behaviour unchanged except what is named".
4. **It can only be decided once every spell is in one shape** — which is the
   whole reason this register exists.

⛔ **The exception that overrides "pre-existing": if the code or a doc CLAIMS
the thing is already true, it is fix-now.** The gap is then not the defect; the
false claim is.

## E · Design questions — worth asking once every spell is in one shape

These are not defects. They are places where the shape we have may not be the
shape we want.

⛔ **THE GATE ON THIS SECTION HAS OPENED, AND THE DISPOSITION IS RECORDED HERE
FOR THE FIRST TIME (D97, 2026-09-10).** This paragraph read _"and only a
complete roster can answer them"_. **A complete roster now exists** — all eight
spells build and share the spine as of 2026-09-09 — so **the precondition is MET
and these four are OPEN AND ANSWERABLE, not gated.** A question still filed
under a gate that has opened reads as blocked, and a reader cannot tell it from
one that is genuinely waiting: D42's rule, applied to a section header.

**They are not answered here, and that is deliberate** — all four are
product-shape questions (what a spell IS, where its boundary sits, whether
co-presence is a direction), and a port must not decide a product question by
implication. **What each one now carries is the material the roll produced for
it**, so answering it is a sitting rather than an investigation:

- **Is `join.ts`'s participant model general?** One spell has a second
  caller-facing participant. If co-presence is the direction, is that a bounty
  feature or a missing kit module? ⚠ **Evidence from the roll: no second
  instance appeared in eight ports.** bounty is still the only spell with one —
  which is evidence for "bounty feature" and against "missing kit module", and
  it inverts what the question implied.
- **Should the two discovery conventions (D3) survive long-term**, or did they
  encode a distinction that the shared spine has since dissolved? ⚠ **Evidence:
  both survived all eight ports unchanged, and the shared half —
  `writeFileAtomic` / `unlinkIfMatches`, ONE predicate carrying both conventions
  (`kit/wire/discovery.test.ts:59`) — is what closed census L3 for seven
  daemons.** The distinction cost nothing to keep and the defect was underneath
  it, which is what D3 predicted.
- **Is a spell's daemon the right unit at all** for the two spells that are
  single-shot (digestify) versus standing (everything else)? ⚠ **Evidence: the
  roll made this SHARPER rather than settling it.** Phase B had to be re-keyed
  from names onto PROPERTIES because four of its steps were wrong for a
  single-shot, single-entry spell (row **D2**), and row **D9** found digestify's
  idle window and its page's heartbeat are a chained pair across the
  backend↔surface seam with no home to declare it in. **The unit is now known to
  be wrong for one spell in a specific, measured way.**
- **Does the surface belong in the same repo boundary as the backend**, given
  four spells' surfaces reach into the skill folder for types? ⚠ **Evidence:
  mind-mapper answered its own half decisively** — its surface imports **zero**
  backend modules and it is **the first spell to end B1 with an empty `shared/`
  set**. So there is one worked example of complete separation, and the four
  spells that reach in are the remaining population.
