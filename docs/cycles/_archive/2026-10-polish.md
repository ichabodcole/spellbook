# Polish before the release

## Why now

The workspace stack is finished. [The cutover](../2026-10-cutover.md) closed on
2026-10-22 with the kit Scriptorium as Scriptorium. `develop` is about 500
commits past `main`, so the next release is a large one. The cycles that got
here, and Cole's trial of the flipped build, left a pile of small items under
[Workspace Kit follow-ups](../../features/workspace-kit-follow-ups/feature.md).
This cycle clears the small ones a user would meet, so the release ships without
them. Anything that needs design waits.

## Rulings

_Cole's rulings:_

1. **Links are ink with a rubric underline (Cole, 2026-10-22, from HTML
   mockups).** It is the most manuscript-like and the least loud, so it is
   easier on the eyes over time and still readable. Not taken: verdigris,
   bronze, olive, faded indigo, or the rubric itself, which can read as an
   error.
2. **A broken link in a proposed version is reported, not rewritten (Cole,
   2026-10-22).** `link-check` names a link a move broke in a version the agent
   proposed, with the act that fixes it. Not taken: making relink rewrite
   proposed versions too.

3. **The broken-links sign stays convention-free (Cole, 2026-10-22).** A
   frontmatter value that isn't path-shaped and doesn't resolve is listed as an
   unresolved reference, not counted as broken. Links between the session's own
   documents don't count as leaving. Not taken: reading `.project-docs.json` (it
   couples Scriptorium to one tool), and search by name (a wrong guess is worse
   than no answer). The agent teaching a session its conventions is filed for
   after the release (`scriptorium-link-rules`).

4. **"Leaving the set" is listed, not counted (Cole, 2026-10-23).** Links to
   files the session doesn't hold stay in the sign's list under their own
   heading, but leave its number: the number is the headline, and a fact that
   isn't a problem shouldn't read as one. Not taken: counting them, or dropping
   them from the sign.
5. **A link between two folder sets in the session is not leaving (Cole,
   2026-10-23)**, provided clicking it opens the other document. **Then, from
   the sign's verifier (Cole, 2026-10-23):** the sign's list opens on what its
   number counts, with the quiet sections after; and when nothing is counted,
   the quiet mark is the faint icon plus a faint word ("11 leaving"), so it says
   what it is. Not taken: context order, and a bare icon whose meaning shows
   only on hover.
6. **The Atlas polish's wording and the lowercase serif wordmark stand (Cole,
   2026-10-23).**
7. **The colours the theme change touches get mock-ups (Cole, 2026-10-23):** the
   stable chip, Cmd-click selected rows, the compare gutter marks, and the
   find/agent fuchsia. **Picked (Cole, 2026-10-23, from `theme-colours.html`),
   every suggestion:** the stable chip in the added green; Cmd-click rows in a
   lighter selection blue with a thin left bar; the compare marks in neutral
   ink; find's current match in stronger amber with an ink underline, and the
   agent's flash as an amber wash with a left bar; the human's chat bubble
   neutral with an edge. Not taken: rubric for any of them, colour-by-kind
   compare marks, and a new verdigris token.

## Outcome

All twenty items shipped. Cole's trial complaints are fixed: links are ink with
a rubric underline, the location dialog opens the native folder picker, a
dropped file can be added where it lives, right-click always opens the
document's menu, and a corrupt pane layout no longer blanks the page. So are the
verifiers' small kit bugs, the Atlas polish (eight of its nine calls) and the
ward gaps. Two changes went further than planned. The theme change grew a set of
optional kit hooks after Cole picked colours from a mock-up page for the four
places where rubric read as danger or deletion. The broken-links sign took two
more rulings from its verifier's findings: counted entries first, and a quiet
mark with a word. The ninth Atlas call, the context sort (L5), was cut and
became `kit-atlas-context-sort`, because it depends on Story Studio's `.order`
files.

What was learned changes how the next cycle is run more than what it builds.
Three flaky-test items came in mid-cycle, and two of them turned out to share a
cause with Story Studio's parallel-test work: a fresh macOS file watch misses a
write made in its first moments. A watch-test probe had passed on the listing
scan rather than on the watch. A comparison that seemed to show the cycle making
tests flakier measured the machine, not the branch, so interleave comparisons
and check `fseventsd` first. The last gates were red from other sessions' load
until Cole stopped the process loading `fseventsd`, and then the gate passed:
6234 pass, 0 fail, 624 s. A build under `NODE_ENV=test` drops Tailwind's banner
and fails `dist-check`; the common brief now says so. The watch race's verifier
found a real product gap, filed rather than rushed: Save can overwrite an
outside change the watch missed (`kit-save-overwrites-unseen-change`). Running
the suite in parallel, as Story Studio now does, is filed as
`spellbook-parallel-tests`, the obvious first work after the release.
