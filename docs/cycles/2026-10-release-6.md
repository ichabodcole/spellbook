# Release ready: Spellbook 6.0.0

## Why now

`develop` is about 580 commits past `spellbook-v5.2.0`, carrying the Workspace
Kit, Scriptorium rebuilt on it, and
[the polish cycle](_archive/2026-10-polish.md). Cole wants the next release to
be one adopters can take in, so this cycle is about stability, not features. A
check of develop on 2026-10-24 found CI red since 10-17, data-loss and
line-ending bugs confirmed in the code, and an adopter-facing README that's
wrong. The release is 6.0.0, because Scriptorium's CLI dropped verbs and its
storage model changed.

## Scope

Approved by Cole in Scriptorium on 2026-10-24, from a proposal that read every
open item. In order:

**Make the gate fast and CI trustworthy first:**

1. **[item/spellbook-parallel-tests](../items/spellbook-parallel-tests.md)**:
   the suite runs with `--parallel` and a timings file, gating in about a
   minute. A probe on 2026-10-24 ran 6,234 pass, 0 fail, in 145 s (about 624 s
   serially). `src/bounty/backend/server.test.ts`, at 129 s, is the floor to
   split.
2. **[item/ci-red-on-linux](../items/ci-red-on-linux.md)**: CI green on develop,
   with the cause of the Linux-only happy-dom failures found and fixed.

**Bugs an adopter would hit:**

## Outcome

6.0.0 shipped on 2026-10-26, as tag `spellbook-v6.0.0`. 15 of the 17 scoped
items were done; two flakes (10, 11) were dropped by Cole because they no longer
reproduced in about 100 runs once the suite went parallel. One item was added
mid-cycle, `import-boundary-r6-ward-timeout`, because it turned CI red on the
push meant to prove the Linux fix. The adopter-facing work landed as planned:
the save and line-ending bugs, the README, and the SKILLs. Inline source maps
came out, cutting shipped JS from 23.2 MB to 12.8 MB. The release message,
written fresh from the tree, found three behaviour changes the upgrade note had
missed: every spell's 403 on a foreign Host header, `--help` exiting 0, and
grapevine `stop` refusing a daemon that won't exit. They went into the note
before the merge. Late rulings from Cole: Bun 1.4.0 is the minimum, the root
kickoff and `index.ts` stub are gone, and media-forge stays unpublished, with a
research item filed on putting image generation behind a provider.

**Learned.** CI's Linux runner is about 9× slower than a dev Mac. Wards that
scan the whole tree sit at 2.5–7 s there, and failed one per push at bun's 5 s
default. The suite's default is now 15 s, set on the test script because bun
1.4.0 ignores bunfig's `[test] timeout`. Making those tests cheaper is still
open (`parallel-suite-integration-timeouts`). "Two green pushes in a row" earned
its place: the first green was followed by two reds, each a different timeout. A
6.0.0 session reopened by 5.2.0 is a real data-loss trap. It is documented in
the upgrade note; the code fix is filed
(`scriptorium-downgraded-session-refused`). The cycle filed 29 items that now
wait in triage.
