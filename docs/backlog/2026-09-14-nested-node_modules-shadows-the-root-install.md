two items. The **dependency upgrade** half moved to
[`2026-09-15-dependency-upgrade-sweep.md`](./2026-09-15-dependency-upgrade-sweep.md),
which widened it from one package to the whole roster. What stays here is the
**guard**: the mechanism that let a phantom dependency tree reach a shipped
artifact. (Commit `c3ede8ae` cites the old filename.)

**Status:** backlog (not scheduled). Captured 2026-09-14 while landing the
release. **Severity:** none now — the accidental split is closed. This is the
deliberate upgrade it revealed, plus the footgun that created it.

## What happened

`gate`'s second failure on release PR #103 was `dist-check` ARM 2: scriptorium's
committed surface bundle was **not** the build of its committed source anywhere
but one laptop.

Cause: a **gitignored `src/scriptorium/node_modules/`** holding
`@base-ui/react@1.8.0`, shadowing the root install's **1.6.0** for scriptorium's
build only. 105 extra modules, 185,688 extra bytes, a different content hash.
Reproduced by cloning the repo, `bun install --frozen-lockfile`, rebuilding, and
watching the chunk go `index-vgy47fsx.js` → `index-j42hseac.js` — CI's exact
diff.

⛔ **So scriptorium was already on 1.8 while the other six consumers were on
1.6, and nobody decided that.** `@base-ui/react` is imported by bounty,
digestify, grapevine, mind-mapper, scriptorium and `src/kit`. The split existed
on one machine and in one committed artifact.

Fixed for the release by removing the stray tree and rebuilding against the
declared 1.6.0 — the version every other spell uses and the only one CI can
install. **Not** by bumping, because a root bump changes six spells' surfaces,
and doing that inside a 521-commit release with no browser pass over the other
five is the wrong moment. Cole, at the decision: _"I'm probably fine with
bumping to 1.8 rather than downgrading to 1.6 … whether we do that now or
whether we get this release done and then that becomes some dependency upgrade
work, I'm fine with that too."_

## The upgrade half moved

See
[`2026-09-15-dependency-upgrade-sweep.md`](./2026-09-15-dependency-upgrade-sweep.md).
Kept here only as the reason this was found:

- Bump `@base-ui/react` at the ROOT (one version for the roster; the split is
  what caused this).
- 1.8's module layout is more granular than 1.6's — the 105-module delta is
  mostly that, not new behaviour — so expect every surface bundle's hash to move
  and `dist-check` to want a rebuild commit across all nine spells.
- **Verify in a browser per consumer, not once.** The components at risk are the
  shared ones in `src/kit/ui/` (`ConfirmDialog`) plus each spell's menus:
  scriptorium's rendered-view context menu and version menu, grapevine's rail
  context menu, bounty's card menus, digestify's review controls.
- Scriptorium's context menu has a gate worth knowing before testing it: it
  opens **only over a selection or over a note**, deliberately
  (`MarkdownView.tsx`), so a right-click on bare text showing nothing is correct
  and not a regression.

## The footgun, which is the more general item

Four spells carry their own `src/<spell>/package.json` (the
[deps-in-a-host-repo pattern](./2026-09-02-what-a-consumer-receives-per-spell.md)
is related). **Running `bun install` from inside one of those directories
creates a nested `node_modules` that silently shadows the root for that spell's
build, is gitignored, and therefore cannot be seen by any reviewer or by CI.**

⚠ **What makes it dangerous is not the shadowing, it is that the committed
artifact captures it.** `dist/` is committed, so a build against a phantom
dependency tree gets reviewed, merged and shipped. `dist-check` catches it — but
only where the phantom tree is absent, which is never the machine doing the
work.

Candidate guards, none designed here:

- A cell asserting no `node_modules` exists under `src/` — cheap, and it fails
  on the exact state that caused this.
- Have `bun run build` refuse to start when one is present, naming it.
- Resolve surface deps from the root explicitly in `src/build.ts`.

The first is the smallest thing that would have turned a release-day CI failure
into a local red before the commit.
