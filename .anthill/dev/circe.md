## Taste & reflexes

Mine sibling spells' idiom BEFORE building a new surface piece — adapt, never import across spells; shapes, naming (e.g. glamour's `FocusOwner`), microcopy register, and token usage should read as one house.
Semantic tokens only in markup; shadcn class vocabulary enters via `@theme` aliases onto house tokens, grown strictly as consumed.
Tailwind class strings live in literal lookup objects, never string-built — `@source` only sees literal text.
Every spell's `styles.css` opens `@import "tailwindcss" source(none);` + an explicit `@source "./"` — a bare `@import "tailwindcss"` roots the scan at the process CWD and compiles that spell's stylesheet out of every OTHER spell's text (605,785 B → 196,480 B across four spells when scoped).
Prefer a bare directory `@source "./"` over an extension glob: `**/*.{ts,tsx}` silently drops `index.html`, and astrolabe's `antialiased` lives there.
A spell adopts the kit by importing `src/kit/theme/base.css`, NOT by importing a kit component — under `source(none)` the module graph contributes nothing, and the kit sheet's own `@source "../"` is the only thing that puts `src/kit/` in front of Tailwind.
That rule is now ENFORCED, not stated: `grimoire/kit-adoption-ward.test.ts` reds when a spell reaches a class-contributing kit module without importing the kit stylesheet, reads only source (no build, so Contract 18's rebuild-gating does not apply to it), and is derived from the tree so a spell that ports its surface later is governed on arrival.
When a ward's trigger is "imports X", ask first whether every X is alike — `src/kit/lib/cn.ts` (no class literal, no token) and `src/kit/ui/Dot.tsx` (both) demand opposite verdicts, and the cell proving the cheap one stays GREEN is the one worth writing carefully.
Decide "contributes classes" from the module's own text, never from `ui/` vs `lib/` or a pinned module list — the kit is about to take the shadcn set, and a path rule would be wrong within a week and wrong silently.
Reuse `grimoire/lib/import-graph.ts`'s `scanSpecifiers` for any import walk and `blankComments` for any comment strip — it keeps `import type` (which `Bun.Transpiler` erases), it is already cross-checked against the transpiler over the whole tree, and a second hand-rolled scan is a second denominator nobody audits.
Tailwind scans `.ts`/`.tsx`, `.md` and `.html` as content and does NOT scan `.css` — measured with probes and a same-run control, so a README dropped into `src/kit/` is a content source and a kit stylesheet's comments are not.
A class name in a kit COMMENT is a real CSS rule in every adopting spell: kit prose must never spell a class the kit's code does not place (`grimoire/kit-prose-ward.test.ts` enforces it; `blankCode` is the inverse strip, next to `blankComments`).
Tailwind RESTARTS a candidate after `.` and `>` and after nothing else in its charset, and a candidate ending `.` `,` or `)` is dead while one ending `:` is live — so `.bg-muted` written in prose ships `.bg-muted`, and a scanner that splits only on non-candidate characters is blind to the selector spelling.
When a syntactic classifier needs a vocabulary, derive it from the tree by SEGMENT, never by token — `bg-muted` is spelled nowhere in the roster and is only reachable as `bg` + `muted`.
Choose between predicate variants by counting each one's noise over a real corpus, not by arguing them: `every`/`last`/`some` segment cost 43/44/45 flags over 1,463 tokens, and only one of them caught the class a stranger would test with.
Skip `erased` refs when a ward's question is "does this render" — counting `import type { ButtonProps }` as adoption is exactly the cry-wolf red that gets a ward weakened by the next person who meets it.
When a new categorical axis rhymes with an existing one, reuse the color vocabulary instead of minting a palette (doc-kind bible/story/ramble → canon/story-local/pending tints made the staging story legible for free).
Keep state and render separate: transient visual effects (search dim) are render-time data overlays, and callbacks enter long-lived structures through ref-stable dispatchers, so neither ever rebuilds state.
Imperative canvas actions are `{payload, seq}` request props; seed the seq guard from the mount-time prop or key-remounts replay stale requests.
Verify with pixels AND the a11y tree — each catches what the other structurally cannot ("rendered in DOM" ≠ "legible": stacked edge labels passed the tree and failed the screenshot).
Peripheral failures degrade into the conversation as an agent-info message; a co-presence surface never lets a side fetch take down the shared board view.
Conversational surfaces get conversational copy — lowercase, working-through register ("work it through…"), never query-box register; the framing IS the feature (Cole's chat ruling).
Every keyboard summon gets a clickable twin (codified in the V1.x dispatch); put the twin where the summoned thing will appear — and when the summoned thing later becomes permanent chrome, the element IS its own twin and the button dies (mind-mapper search: icon button f488f99 → permanent palette, R4 S1 commit e449184).
Making a summoned overlay permanent inverts its whole lifecycle grammar, not just its render gate: summon becomes focus+select through a ref (never a re-open), Escape's job flips to clear-and-blur, the mount-time autofocus MUST die (a permanent input stealing focus at app boot), and any positional dodge the dead toggle carried (FocusBar top-14) moves onto the permanent element itself (R4 S1).
Make precedence structural, not conditional: seeding projectId from the URL at mount means the daemon-default mirror effect CAN'T override an explicit ?project= (the `!projectId` guard is false by construction) — no override branch to write or test; the precedence itself lives in a pure `resolveInitialProject(search, stored)` tested without a DOM.
Model a multi-stage dialog as one state object whose stage IS the data (`{doc, citedBy: CitedBy | null}`): the 409's parsed counts arriving is what escalates the SAME dialog to its provenance stage — no stage enum, no second dialog, and the untrusted-body parse lives in a pure tested helper while the fetch stays App glue (P2 delete flow).
A fire-once signal with multiple clears (idle event, reply-message-landed, client TTL) wants one effect PER clear trigger, each keyed on its own dependency — merging them into one effect invites stale-closure ordering bugs (P2 thinking pulse).
When two components need the same literal Tailwind class lookup, export the lookup from its home component instead of duplicating it — the literal-text `@source` constraint makes shared lookup objects the reuse unit (KIND_BADGE: ContextRail cards + MessageBubble doc chips; TIER_CARD/KIND_ICON/TIER_LABEL: GraphCanvas + CardGrid, R3 V1).
Theming a Tailwind v4 surface: `@theme` compiles into `@layer theme`, and an UNLAYERED `[data-theme=light]` block beats layered rules regardless of order or specificity — that plus alias tokens as var() refs (never copied values) is what lets the second palette be written once as house-token overrides (R3 T1, commit 5742400).
A control that switches views must never be coverable by what it controls — when the Panel top-right became load-bearing (map|grid), the NodeDetail perch moved structurally below the control row in BOTH views; an overlay that can hide the only way out of a view is a trap (found when Playwright literally could not click the toggle).
Seeding a controlled textarea: the effect that setState's the draft cannot place the caret in the same tick — the DOM value hasn't committed — so focus+setSelectionRange ride a requestAnimationFrame (R3 C3).

### Sprint 03 (spell-kit) — Phase 4d: the ward for kit PROSE

**⛔ MY OWN REMEDIATION TEXT RE-CREATED THE LEAK, AND MY OWN WARD WATCHED IT HAPPEN.** Rewriting `Dot.tsx`'s warning so it stopped naming three classes, I explained the repair with the sentence *"`.bg-muted` was a real rule in imago's stylesheet"* — and imago rebuilt with `.bg-muted` still in it, ward 4/4 green. **Tailwind RESTARTS a candidate after `.` and after `>`, and after nothing else in its charset** (measured: `.p-83` and `x>p-99` emitted; `p-92.`, `docs/p-94`, `a,p-95`, `[p-96]`, `a_p-97`, `a#p-98`, `a<p-84`, `a+p-85`, `a~p-86`, `a*p-87`, `a&p-88`, `a!p-89`, `a%p-90`, `(p-74)` did not; control in the same run). A tokenizer that splits only on non-candidate characters cannot see a class written in its SELECTOR spelling, which is the form prose reaches for when it is explaining a rule about CSS. **The fix belongs in the instrument, not in the sentence.**

**⭐ THE BRIEF SAID EXACTLY THREE; IT WAS EIGHT, AND ONLY THREE OF THE EIGHT WERE LIVE — AND THOSE THREE WERE NOT THE THREE.** Shipped class-selector diff across the remediation: imago 347 → 346 (lost `bg-muted`), mind-mapper 390 → 388 (lost `w-2` and `h-2`), astrolabe and magpie unchanged at 199 and 262. The five that cost nothing are the ones each consumer's own code already writes, or that are invalid in the receiving theme (`bg-popover` emits in mind-mapper, which defines `--color-popover`, and emits NOTHING in imago, which does not). **A prose candidate materialises only where the receiving spell's theme happens to make it valid — so "how many classes does this comment leak" has a different answer per consumer, and the syntactic rule is the only one that is a property of the KIT.**

**⛔ `.css` IS NOT A TAILWIND CONTENT SOURCE, AND `src/kit/theme/base.css` CONTAINS A ⛔ WARNING SAYING IT IS.** Probes in a `base.css` comment and in an unimported `src/kit/**.css` emitted nothing; the identical probe in a `src/kit/NOTES.md` and a `src/kit/ui/fixture.html` in the same directory both emitted. So the file's *"a class written here in prose stays emitted"* is false, while the uncovered surface nobody had named is a kit README. **A warning inherited from a sibling file's mechanism is not a measurement**, and the two files' comment syntax being different was the whole tell.

**⭐ A PREDICATE'S NOISE IS A NUMBER YOU CAN GET IN A MINUTE, NOT A THING TO ARGUE ABOUT.** Deciding whether a class-shaped token needs EVERY segment, its LAST segment, or ANY segment drawn from the roster's vocabulary, I ran all three over the comments of every `.ts`/`.tsx` under `src/` — 1,463 candidate-shaped tokens — and got 43 / 44 / 45 flags. `every` is one token quieter than `last` and misses `bg-teal-500`, the stock-palette class a non-author reaches for first. **One token of extra noise across the whole tree bought the route that matters; without the corpus I would have defended the quiet one on taste.**

**⛔ AND I ONLY FOUND THAT BECAUSE I RAN ROUTE 1 INSTEAD OF ASSUMING IT.** "Add a class to a kit comment and the ward reds" is the route the ward is FOR; it read as too obvious to run, and it came back **4 pass / 0 fail**. That is the epitaph's shape at a new grain: the cell was correct about the classes the finding named and silent about the class a stranger would pick. **Run the route whose result you are most confident about — confidence is what makes it the cheap one to skip and the expensive one to be wrong about.**

**⭐ A GREEN ROUTE'S POSITIVE CONTROL IS A COUNT OF WHAT WAS REJECTED, AND IT MUST NOT BE A RATIO.** The route that must not red is "ordinary hyphenated English, paths, specifiers, URLs, versions". `shapedInProse > 2 × classedInProse` is satisfied by a classifier that finds nothing; `shapedInProse − classedInProse > 20` is not. Live: 50 shaped, 1 classed, 49 rejected. **State the rejected count, not the proportion.**

**⭐ AND THE OTHER GREEN ROUTE NEEDED A DISCRIMINATING CONTROL, NOT A PASS.** "A class in both code and prose stays green" is green whether the ward is right or asleep. Deleting `rounded-full` from `Dot.tsx`'s CODE while leaving the identical comment turned the same file into an offender — **the comment did not change, the verdict did**, which is the only version of that route that proves anything. `rounded-full` is now deliberately spelled in that header so the route stays live in the tree rather than living in a fixture.

**A VOCABULARY DERIVED FROM THE TREE MUST BE INDEXED BY SEGMENT, NOT BY TOKEN.** `bg-muted` — the one class this whole ward exists for — is spelled nowhere in the roster's markup, so a token-level vocabulary would have classified it as English. It is reachable as `bg` + `muted` because imago writes `text-muted` and every spell writes `bg-`. **The unit of a derived vocabulary is the unit the thing is BUILT from, not the unit it is used as.**

**TWO WARDS OVER ONE DIRECTORY MUST AGREE ON WHAT A CLASS LOOKS LIKE.** `CLASS_TOKEN` is copied character-for-character from `kit-adoption-ward.test.ts`, including its stated blind spot for bare single-word utilities. Two grammars in one directory means "class" means two things there, and the next person to meet a disagreement will loosen one of them.

**THE INVERSE OF A STRIP BELONGS IN THE STRIP'S OWN FILE.** `blankCode` is now next to `blankComments` in `grimoire/lib/import-graph.ts`, both projected from one `commentRanges` walk, so the two halves are provably a partition. Every other ward in this repo strips comments so prose cannot satisfy a claim about code; **this one runs the other way, because Tailwind makes prose load-bearing** — and a private `/\*[\s\S]*?\*\//` to re-find them would have been a second scanner that knows nothing about strings, templates or regex literals.

**Proof:** `grimoire/kit-prose-ward.test.ts` — five routes run, each naming the cell it reds (PROSE ×3, INSTRUMENT + PROSE, VOCABULARY + PROSE, POPULATION), plus two green routes with their controls.

### Sprint 03 (spell-kit) — Phase 4c: the ward that makes Contract 21's adoption rule enforceable

**⛔ A CELL PASSED THE BREAK IT WAS NAMED AFTER, AND THE WARD REPORTED 4 PASS / 0 FAIL.** My TRANSITIVE cell said "reaches the kit through another kit module" and compared `reachedKitModules([f]).size > directKitImports(f).length` — which an `App.tsx → components/Header → Dot` chain satisfies through a LOCAL module, never through a kit one. Stopping the walk at the kit boundary left it green. The repair was to compare the walk against **its own depth-1 self** (`reachedKitModules([f], false)`), a comparison no path that skips the mechanism can satisfy. **When a cell's subject is "X happens through Y", the honest comparison is the same instrument with Y disabled — anything else is a proxy, and a proxy is where the name and the assertion drift apart.**

**⭐ AND THE ONLY REASON I KNOW IS THAT I RAN THE BREAK AGAINST THE CELL RATHER THAN AGAINST THE WARD.** Three of the four cells were irrelevant to that route; a ward-level "did it red" would have told me nothing, and a ward-level "it stayed green" is what I actually got. **Run each route, then read WHICH cell reds — the exit code is not the measurement.**

**⭐ A GREEN ROUTE NEEDS A POSITIVE CONTROL MORE THAN A RED ONE DOES.** The route that mattered most here was the one that must NOT red (a spell importing only `cn`), and "green" has two causes: the predicate judged correctly, or the walk found nothing. I printed the closure beside the verdict — `REACHED astrolabe: ["src/kit/lib/cn.ts"] CONTRIBUTING: []` — which separates them in one line. **A passing cell proves nothing about an instrument until you have seen the instrument's input.**

**AN AND-PREDICATE'S BLIND SET IS PART OF ITS RESULT, SO STATE IT WHERE THE PREDICATE LIVES.** "Contributes classes" is *authors class text* AND *uses class text*, because either half alone over-reports (`"application/json"` on one side, a pass-through `className` wrapper on the other). That AND misses a kit module that EXPORTS class strings for a consumer to place — real, absent today, and written into the file's header with the repair named (widen the class-site set, do not drop the AND). **A predicate that only documents what it catches invites the next reader to assume the rest.**

**⛔ TWO WARDS OVER ONE DIRECTORY CAN CONSTRAIN EACH OTHER'S SOURCE TEXT.** `kit-styling-ward` asserts its sentinel utility appears in no tracked text file outside `src/kit/` — including any new ward's fixtures. Writing a realistic fixture is not free here; check the sibling wards' repo-wide cells before choosing example strings.

### Sprint 03 (spell-kit) — Phase 4b: scoping every spell's Tailwind content scan

**⛔ A NEGATIVE RESULT FROM AN INSTRUMENT WHOSE SUBJECT IS NOT PRESENT IS NOT A MEASUREMENT, AND THIS ONE ALMOST SHIPPED AS A FALSIFICATION.** I deleted `@source not ".../dist"` from imago, rebuilt, and got a byte-identical stylesheet — which reads as "the guard was always dead" and is wrong. `src/build.ts` rm's each spell's own `dist/` before compiling it, so the guard has NO SUBJECT unless a stale class is sitting in a DIFFERENT spell's committed output. Constructing that world flipped the verdict in one run: add a stock-palette class to an astrolabe COMPONENT, `build astrolabe`, delete the class from source, `build magpie` — magpie emitted it, and imago and mind-mapper (which had the guard) did not. **Before you believe "no effect", build the world in which the effect would exist**; a check run against an empty world and a check that cannot fail produce the identical output.

**⛔ AND THE FIRST ATTEMPT AT THAT CONTROL WAS ITSELF VACUOUS, FOR A REASON THAT WILL RECUR.** My probe was `export const PROBE = "bg-lime-500"` — an unused export, which the bundler tree-shakes, so it reached the `dist/` CSS and never the `dist/` JS. Tailwind does not scan `.css`, so nothing could have leaked and the "no leak" result was guaranteed. **A probe has to travel the same path as the thing it is standing in for** — putting the class in a live `className` was the whole fix, and the control that confirms the probe ARRIVED (grep the bundle for it) is not optional.

**⭐ THE RIGHT CONCLUSION FOR THE WRONG REASON IS STILL A FALSIFICATION, AND HERE THE REASON WAS THE LOAD-BEARING PART.** The brief's central claim was that kit sharing survives a scoped scan because Tailwind treats the bundle's MODULE GRAPH as a content source. The conclusion held — the kit's sentinel utility still ships — and the mechanism is false: Bun's Tailwind plugin discards the module graph outright when the content root is `none` (`getModuleGraphCandidates` returns an empty set, readable in `node_modules/bun-plugin-tailwind/index.mjs`). What actually carries `src/kit/` into a spell is the `@source "../"` inside `src/kit/theme/base.css`. Proved by deleting that one line and rebuilding: all three of Dot's utilities vanished from imago's shipped stylesheet. **It changes the house rule for the shadcn future — a spell adopts the kit by importing the kit STYLESHEET, and importing a kit COMPONENT alone gets markup with no utilities.**

**READ THE PLUGIN SOURCE AND THEN FALSIFY IT; NEITHER ALONE WAS ENOUGH.** The source read predicted the kit's utilities would die and the build said they lived, and both were right — the source told me which mechanism does NOT fire, and only the deletion experiment found the one that does. **A code reading is a hypothesis about WHICH mechanism produced an output, never about whether the output is correct**, and the gap between them is exactly where a plausible wrong mechanism gets written into a comment and believed for a year.

**⛔ A SUBSTRING MATCH IS NOT A CLASS MATCH, AND IT MANUFACTURED A VISUAL REGRESSION THAT DID NOT EXIST.** My first loss-check used `blob.includes(cls)` and reported 45 real losses for astrolabe including `bg-amber-500`, `ring-violet-500` and `ring-fuchsia-500` — astrolabe's 8-hue project-identity RINGS, which would have been a visible defect. They were substrings of `bg-amber-500/20` and `ring-violet-500/40`, whose Tailwind candidate is the longer string alone; all 24 ring classes were intact. Boundary-matched against Tailwind's candidate character set the count went 45 → 1, and the 1 was `32` from `c.width = 32`. **And the TRAILING boundary must EXCLUDE `:`** — Tailwind splits candidates on the colon, so the CSS property name `transform:` in a keyframe emits a real `.transform` rule; keeping `:` in the trailing set made my ward blame a spell that had never touched it.

**⭐ TWO INSTRUMENTS THAT FAIL IN DIFFERENT DIRECTIONS, OR THE ZERO MEANS NOTHING.** A source-text walk cannot see a class living inside a node_modules package; the SHIPPED JS BUNDLE contains every module that actually renders, third-party included. Both had to come back empty before I would say "zero losses", and the bundle instrument's own control is what caught me choosing `bg-surface` as astrolabe's positive when astrolabe never uses it bare — **the control failed instead of the instrument silently reporting zero**, which is the entire reason to write one.

**⭐ A COMPUTED-STYLE DIFF IS A STRONGER VISUAL CHECK THAN A SCREENSHOT PAIR, AND IT COSTS THE SAME.** Two full-page PNGs of astrolabe pre- and post-fix looked identical, which is an eyeball claim. Dumping `getComputedStyle` for 31 properties across all 105 elements in both builds and diffing gave 3 differing elements, every one explicable: an `animate-ping` span sampled mid-animation, and two text widths from `"28s ago"` vs `"53s ago"`. **"I looked at it and it seemed fine" and "zero of 3,255 computed values changed for a reason other than the clock" are different sentences**, and only the second survives someone asking how hard you looked.

## Anti-patterns

Claiming a card from a board listing held in context — after the lead batch-adds, RE-PULL state and claim by id; a card remembered by title is not a card (mis-claimed t-806ff9da for t-9a4bd7b2).
Dropping Playwright/verification artifacts at the repo root — they default to CWD; move them to `.anthill/scratch/` immediately (the gate-safe home) and delete `.playwright-mcp/`.
Trusting a peer's land to be whole — untracked NEW files hide from pathspec commits (a skeleton commit shipped without its styles.css); check `git status` before building on it.
`setError`-ing the whole board on a peripheral fetch failure.
Leaving third-party chrome (React Flow controls, attribution, edge labels) at default styling — retune to tokens or the night palette breaks at the seams.
Waiting idle on a pending flag — the flag gates the land, not the work.
Matching a class name with `includes()` — `bg-amber-500` is a substring of `bg-amber-500/20` and the substring is not a candidate; boundary-match on Tailwind's candidate character set, and drop `:` from the TRAILING set.
Concluding "no effect" from a check you did not first watch succeed on a constructed instance of the thing it checks.
Spelling a glob containing `*/` inside a CSS comment — it closes the comment and the build dies on the remainder.
Believing a calibration route from the ward's exit code — read WHICH cell red; a cell can pass the break it is named after while a sibling carries the run.
Writing a ward trigger as "imports module X" when the modules under X are not alike — the false red on correct code is what gets the ward weakened by whoever meets it next.
Hand-rolling an import scan or a comment strip when `grimoire/lib/import-graph.ts` already exports one that is cross-checked against `Bun.Transpiler`.
Writing a class name in its SELECTOR spelling (a leading `.`) inside prose that explains why the class must not be written — Tailwind restarts a candidate after the dot and ships it anyway.
Assuming a `.css` comment is scanned because the `.ts` comment beside it is; the two files are in the same `@source` directory and only one of them is content.
Skipping the calibration route you are most confident about — confidence is exactly what makes it cheap to skip and expensive to be wrong about (route 1 of the prose ward came back 4 pass / 0 fail).
Proving a green route with a ratio (`shaped > 2 × classed`) instead of a rejected COUNT — a ratio is satisfied by a classifier that finds nothing, which is the failure the control exists for.
