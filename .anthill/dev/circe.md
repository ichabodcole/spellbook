## Taste & reflexes

Mine sibling spells' idiom BEFORE building a new surface piece — adapt, never import across spells; shapes, naming (e.g. glamour's `FocusOwner`), microcopy register, and token usage should read as one house.
Semantic tokens only in markup; shadcn class vocabulary enters via `@theme` aliases onto house tokens, grown strictly as consumed.
Tailwind class strings live in literal lookup objects, never string-built — `@source` only sees literal text.
When a new categorical axis rhymes with an existing one, reuse the color vocabulary instead of minting a palette (doc-kind bible/story/ramble → canon/story-local/pending tints made the staging story legible for free).
Keep state and render separate: transient visual effects (search dim) are render-time data overlays, and callbacks enter long-lived structures through ref-stable dispatchers, so neither ever rebuilds state.
Imperative canvas actions are `{payload, seq}` request props; seed the seq guard from the mount-time prop or key-remounts replay stale requests.
Verify with pixels AND the a11y tree — each catches what the other structurally cannot ("rendered in DOM" ≠ "legible": stacked edge labels passed the tree and failed the screenshot).
Peripheral failures degrade into the conversation as an agent-info message; a co-presence surface never lets a side fetch take down the shared board view.
Conversational surfaces get conversational copy — lowercase, working-through register ("work it through…"), never query-box register; the framing IS the feature (Cole's chat ruling).
Every keyboard summon gets a clickable twin (codified in the V1.x dispatch); put the twin where the summoned thing will appear — and when the summoned thing later becomes permanent chrome, the element IS its own twin and the button dies (mind-mapper search: icon button f488f99 → permanent palette, R4 S1 commit e449184).
Making a summoned overlay permanent inverts its whole lifecycle grammar, not just its render gate: summon becomes focus+select through a ref (never a re-open), Escape's job flips to clear-and-blur, the mount-time autofocus MUST die (a permanent input stealing focus at app boot), and any positional dodge the dead toggle carried (FocusBar top-14) moves onto the permanent element itself (R4 S1).
Make precedence structural, not conditional: seeding projectId from the URL at mount means the daemon-default mirror effect CAN'T override an explicit ?project= (the `!projectId` guard is false by construction) — no override branch to write or test; the precedence itself lives in a pure `resolveInitialProject(search, stored)` tested without a DOM.
Model a multi-stage dialog as one state object whose stage IS the data (`{doc, citedBy: CitedBy | null}`): the 409's parsed counts arriving is what escalates the SAME dialog to its provenance stage — no stage enum, no second dialog, and the untrusted-body parse lives in a pure tested helper while the fetch stays App glue (P2 delete flow).
A fire-once signal with multiple clears (idle event, reply-message-landed, client TTL) wants one effect PER clear trigger, each keyed on its own dependency — merging them into one effect invites stale-closure ordering bugs (P2 thinking pulse).
When two components need the same literal Tailwind class lookup, export the lookup from its home component instead of duplicating it — the literal-text `@source` constraint makes shared lookup objects the reuse unit (KIND_BADGE: ContextRail cards + MessageBubble doc chips; TIER_CARD/KIND_ICON/TIER_LABEL: GraphCanvas + CardGrid, R3 V1).
Theming a Tailwind v4 surface: `@theme` compiles into `@layer theme`, and an UNLAYERED `[data-theme=light]` block beats layered rules regardless of order or specificity — that plus alias tokens as var() refs (never copied values) is what lets the second palette be written once as house-token overrides (R3 T1, commit 5742400).
A control that switches views must never be coverable by what it controls — when the Panel top-right became load-bearing (map|grid), the NodeDetail perch moved structurally below the control row in BOTH views; an overlay that can hide the only way out of a view is a trap (found when Playwright literally could not click the toggle).
Seeding a controlled textarea: the effect that setState's the draft cannot place the caret in the same tick — the DOM value hasn't committed — so focus+setSelectionRange ride a requestAnimationFrame (R3 C3).

## Hard-won lessons

A per-entity WS event can be THIN — carrying only ids, not the full entity — and a consumer must be built to expect that, not assume completeness; `node.ratified`/`edge.ratified` carry `{id, proposalId}` only, so the reducer's job is flipping the referenced proposal's status (the one thing the payload proves), and `useProjectState` fires a follow-up snapshot GET to backfill what the thin event can't carry (mind-mapper V1, commit 22f36c6 — verified by opening a real WS socket and watching the actual frame, not by reading the emit() call in source, which is what let the original wrong assumption slip through review).
Never invent a plausible-sounding literal for a string-union type from a wire's real value — `ProposalStatus` was typed `"accepted"` when the daemon actually writes `"ratified"`, and a JSON-cast boundary (`fetch().json() as T`) never catches this at compile OR runtime, so it silently breaks every `!== "pending"` check until exercised live (same commit).
A `build.ts`'s `naming` option needs the `{entry, chunk, asset}` object form whenever the entrypoint is HTML — a single naming string hashes the HTML entry too, and a hashed entry is invisible to a daemon's `dist/index.html`-exact-filename release-mode check (Contract 1), so the daemon silently stays in dev mode against a real, correctly-built dist/ (mind-mapper P4, commit 3b8b652 — caught by booting the daemon and reading the served hrefs, not by trusting the build's exit code).
A stale `dist/` silently shadows your surface changes in live verification: `daemonCwd()` auto-picks release mode whenever `dist/index.html` exists, so an auto-booted daemon serves the PRE-change build with no error — force `SPELLBOOK_SURFACE_MODE=dev` when verifying uncommitted surface work (the inverse of the P4 hashed-entry lesson: same boundary, opposite failure).
`MIND_MAPPER_HOME=<scratch>` boots a fully private daemon (own port/pid/db files) without touching a teammate's running one — the clean way to honor "never kill a daemon you didn't start" while still getting a kill-to-see-the-banner drive (P1s verification).
This sandbox blocks spawning long-running daemon processes directly (the auto-mode classifier denies it) — when a fresh boot is genuinely needed, retry the exact same command once (it sometimes succeeds nondeterministically) before asking a teammate to co-drive; killing a stale daemon by its exact PID (from `daemon.pid`, never `pkill -f`) and then re-`open`ing usually works even when a fresh spawn doesn't (P2 session: a fresh `open` under a scratch MIND_MAPPER_HOME succeeded first try — the denial is nondeterministic, not absolute).
The ephemeral-event cursor clause is now LAW (Contract 9 amendment, P2 T4): every bus emit consumes a seq, fire-once signals included — ephemeral kinds route THROUGH applyEvent (default case advances cursor) and the hook surfaces them via the {payload, seq} idiom; the old look.here early-return-before-reducer froze the cursor so every later event read as a phantom gap (one wholesale /state refetch per signal — latent at look.here rates, fatal at agent.activity's 2–3× per turn), pinned by the "look.here advances cursor" regression test (commit 69e3802).
`/state.presence` is NOT in the engine's state.ts ProjectState — server.ts spreads it onto the readState result at the handler (`{...readState(...), presence}`), so reading state.ts alone under-reports the wire; check the handler when a /state field seems missing (found consuming Claim C).
Base UI's AlertDialog is mostly re-exported Dialog parts (Backdrop/Popup/Title/Description are Dialog's own, only Root/Trigger are alert-specific) — the shadcn port carries the dialog conventions directly, and `open`/`onOpenChange` controlled use works without a Trigger when a menu action opens it (commit 9c73761).
React Flow has no pane-scoped double-click callback — but ReactFlowProps extends div props, so a DOM `onDoubleClick` with an `e.target.classList.contains("react-flow__pane")` guard scopes it to empty canvas (node/edge double-clicks pass by); pair it with `zoomOnDoubleClick={false}` or the sketch form rides a zoom (commit 9c73761).
An imperative scroll request that must SUSPEND another effect (autoscroll-to-bottom) needs a synchronous ref flag, not render state — the messages-changed effect has to see "servicing" in the same commit the request lands, or one concurrent message yanks the viewport off the evidence (P2 T11).

React Flow wants semi-controlled use: the canvas owns node state via `applyNodeChanges`, reports selection upward deduped (last-reported key ref), and applies external deselects behind a same-set guard — an unconditional setState in either direction is an infinite render loop (commit c0561eb).
React Flow label styling is inline — CSS loses; and the label's bg rect is a SIBLING of the text, so both need the same transform or the text walks off its plate (commits c0561eb, 6223522).
Reverse-pair edge labels stack at the shared bezier midpoint, and curvature can't separate vertically-stacked nodes because it acts along the handle axis — separate the labels themselves, deterministically per pair member (commit 6223522).
`multiSelectionKeyCode` defaults to Meta on macOS — if the UI copy promises shift, set it explicitly.
Driving a MULTI-node selection into React Flow through the controlled `nodes` prop is a latent infinite-loop (R5 SC — the first feature to select multiple nodes programmatically; single-select and user shift-select were both fine): React Flow honors the prop's `selected` flags (it does NOT collapse — I proved this by disabling the reverse channel and seeing all 3 hold) but emits TRANSITIONAL `onSelectionChange` echoes as it reconciles — the stale prior selection, then the new one — and feeding those back through `onSelect` ping-pongs App→RF→App forever ("Maximum update depth" in RF's StoreUpdater/setNodes, NOT your code's stack); the existing last-reported-key dedup only catches the FINAL echo, so the intermediate one slips through and seeds the oscillation (commit 438ffe0).
The fix is a pending-selection gate, not more dedup: when App DRIVES the selection, record the wanted key and swallow every RF echo until RF reports that EXACT key (then close the gate without re-reporting — App already holds it), with a short safety timer so a never-confirm can't freeze selection; genuine user gestures fire only once the gate is closed (commit 438ffe0).
Diagnose an RF selection loop by logging what `onSelectionChange` actually reports — the alternating keys (single active node ↔ the full programmatic set) are the tell, and disabling `onSelect` entirely is the decisive experiment: if RF still holds the full selection visually, the bug is the feedback echo, not an RF collapse (R5 SC drive).
A lifted keyboard handler (Escape → window, mirroring the ⌘K/`/` summon) needs a pure guard so it doesn't hijack Escape from other inputs/dialogs — `shouldDismissSearch(activeTag, isSearchInput, hasQuery)` tested without a DOM; and the window listener's closure must dep on the state it reads (`[searchQuery]`) or it fires stale — which ALSO bit my first live test (synchronously dispatching Escape before React committed the query left the listener seeing the old empty value; flush a tick between set-query and press-Escape) (R5 ESC).
A second dim CHANNEL reuses the visual, never the prop: SL's spotlight ORs its own dim into GraphCanvas's `data.dimmed` (opacity-20, same look as search) but rides a SEPARATE `spotlight` prop — sharing search's `highlightIds` would collide two independent effects; and edges needed NEW plumbing (a `renderEdges` overlay dropping non-lit paths+labels to ~0.08) because `toFlowEdges` only bakes provenance/pending opacity with no render-time overlay (R5 SL, commit 5217f7f).
The spotlight's lit EDGES are the subgraph INDUCED by the lit nodes (both endpoints lit), which is exactly the joining selected→shared-neighbor set plus any selected↔selected edge — computing induced (not just the literal joins) means a bright node-pair never shows a dim edge between them (R5 SL, computeSpotlight).
Any literal-text anchor into a formatter-managed file must be whitespace-insensitive (`\s+`-joined match) — prettier's pre-commit reflow is a standing drift source; the mind-mapper span anchors survived a real reflow only because of this (commit d3599aa).
Daemon ROUTES bake at boot even when DATA re-reads per request — after a peer lands a new endpoint, restart the daemon or you chase a phantom 404 against code that "definitely landed"; also, a console 404's trailing `:0` is line-number formatting, not a mangled URL.
shadcn-on-Base-UI is a PORT, not a copy: Base UI `className` props accept state-functions (narrow to plain string in the vendored layer) and `GroupLabel` mandates a `Group` wrapper where shadcn's `Label` is standalone (commit 1c6b556).
A dependency-free `cn()` (no twMerge) changes API design: a variant must REPLACE a recipe, never fight one, because conflicting utilities resolve by stylesheet order — if a call site overrides a variant's box model, the component needed another variant (commit 029dce0).
Library chrome retuned with a single class can silently lose to the library's own COMPOUND selector — `.react-flow__panel.react-flow__attribution` beat my `.react-flow__attribution{background:transparent}` and the half-white plate resurfaced only against the night palette; double the class (`.x.x`) to outrank without !important (R3 T1 light-mode pixel pass).
micromark's safe default (raw HTML → encoded) is what makes both the sanitizer-free dangerouslySetInnerHTML AND the string-level anchor post-pass sound: every `<a href=` in the output is renderer-minted, so a regex rewrite can't be steered by message content (pinned by test, R3 C2).
The span-flash × markdown mechanism (ratified, now proven live): match spanRange against the bubble's textContent, map the range onto TreeWalker-ordered text nodes with the pure offset mapper, wrap via splitText + insertBefore (never Range.surroundContents — it throws on partial element overlap), tear down by unwrap + parent.normalize() so repeat flashes map clean offsets; a span crossing a <strong> boundary yields two marks and that's correct (commit 5742400).
A fire-once visual with a short TTL (2s flash) outlives none of a multi-roundtrip MCP drive — verify click-then-assert inside ONE browser_evaluate with an await, or the assertion honestly reports the already-ended state as a failure.
Playwright's default emulated prefers-color-scheme is LIGHT — a fresh MCP page is a free test that the OS-preference default path actually works (my first screenshot verified T1's matchMedia branch by accident).
A primitive's internal state model is a cost, not a feature, when the feature's value is live coupling to external state — cmdk/Autocomplete fit self-contained palettes, not palettes that remote-control a canvas; the upgrade path is a component swap behind app-owned state (commit 9f55153).
An inclusive tagged store wants segregation at DERIVATION, not ingestion: reducer/upserts stay view-blind, one pure filter (mainProposals/zoneMapFrom) serves every view, and the both-ingestion-points clause is then true by construction — pin it with a test that drives a snapshot row AND an event row into the same derivation (R3 Z3, zoneView.test.ts).
A cross-view focus (agent-follow into a zone) is a two-step: park {nodeId, zone} as state, switch the board, flush the focusRequest in an effect gated on board===target + one rAF — and deliberately do NOT key the canvas on the view, or the remount seeds its seq guard from the new request and swallows it (R3 Z3, followFocus/pendingFocus).
The coverage audit ("a control that switches views must never be coverable by what it controls") must re-run for EVERY new full-width overlay, not just the one that taught the lesson — the FocusBar covered the React Flow Panel row exactly one round after NodeDetail taught it (caught live: Playwright couldn't click the toggle under a doc lens).
React Flow's `.react-flow__panel` margin is UNLAYERED vendor CSS, so Tailwind margin utilities lose to it silently (the theme-layer precedence trap again, third sighting) — reposition a Panel with an inline `style={{top}}`, which always wins (commit bfb497d).
Playwright's network tools never surface WS upgrades — to watch the ACTUAL WebSocket URL, Proxy `window.WebSocket` in an evaluate and then trigger a fresh connection (project switch), reading the recorded ctor args (R3 P1 verification).

On the shared tree, a full-suite run can transiently red on a PEER's mid-edit files — the tell is the test COUNT drifting between runs (927→932→945 in one R4 session while daedalus landed engine work live); re-run before diagnosing a fail that isn't in your own paths.
A wire-level assert beats a chip-level one for a send-path change: the grounded message's truth is `/state.conversation[].ground` read back over curl, with the rendered chips as the round-trip bonus — the UI could render a chip from stale local state, the wire can't (R4 G1 drive).
A suggestion vocabulary is not a command vocabulary: `suggestedTier` includes "background" but the engine's `Ruling` union stops at story-local, so a one-keystroke "ratify at suggestion" must NARROW through the command union (`ratifyAs: Ruling | null`) or the menu offers a verb the daemon refuses — the same never-offer-a-refused-verb principle as Claim D's withdraw-only sketches, caught by tsc at the type seam (R4 R1, nodeMenu.ts).
A shared context-menu chassis is a component taking the trigger as children plus a per-id info map derived view-blind over the inclusive store — the synthetic-node-id-IS-the-proposal-id convention makes proposal-attached data resolve in both views for free, and the menu overlay rides renderNodes (a render-time data overlay, like dimmed/promotable) through ref-stable dispatchers so proposal churn never rebuilds node state (R4 R1/A1, NodeContextMenu + menuInfoFor).
A persistent alarm state and a decaying pulse cannot share a boolean: the badge went tri-state (`thinking | stalled | null`) with `badgeHasClientTtl` gating the client backstop, and the timeout's functional guard (`b === "thinking" ? null : b`) is what makes a leftover pulse timer structurally unable to clear a stalled alarm that superseded it (R4 ACT1).
"Static, never the pulse" is assertable computationally, not just by pixels: getComputedStyle(...).animationName === "none" over the element AND its descendants is the honest no-false-liveness check — a screenshot can't show absence of motion (R4 ACT1 drive).
The same nullable field renders differently by what the element CLAIMS: a kind badge claims a kind, so null = absence (no badge); a doc-reference chip claims a doc, so null kind = neutral plate — one nullable, two honest renderings (R4 K1, kindBadgeClass null vs NEUTRAL_BADGE fallback).
Type a wire envelope as its own shape, never as meta-plus-content: `Doc = DocMeta & {content}` over-claimed `kindAuthor` the /doc/:id envelope doesn't carry — the compiler can't catch a cast that lies by intersection (R4 K1).
The engine's test knobs are live-drive knobs too: MIND_MAPPER_ACTIVITY_TTL_MS=4000 on the scratch daemon made the received→stalled ladder drivable in seconds instead of a 60s wait (R4 ACT1 drive).
A whole navigation dimension (SG2 submaps) integrated as ONE more pure derive in the existing board chain (`mapWithPending → zoneMapFrom → submapView → visibleMap`) — the entire wiring cost was inserting `submapMap` and REPOINTING the four downstream consumers (selection, spotlightSets, visibleMap, SC's lensSet) from `boardMap` to it; the inclusive-snapshot-plus-client-derive pattern (zones precedent) held a second time, no refetch, no server scope (R5 SG2).
The top-level board is now `anchorNodeId == null`, NOT "all nodes" — introducing submaps means an anchored node DISAPPEARS from the top level (it lives in its parent's submap); this is correct, and it's why the filter defaults synthetic/legacy nodes to `null` (top-level) via `?? null` rather than making the field required and churning every MapNode literal (R5 SG2).
A thin `node.anchored {nodeId, anchorNodeId}` proves only the MOVED node's new parent; `submapChildCount` is a derived count on the OTHER end (old+new parent) that the thin event can't carry — do NOT recompute it locally, let the ratified-events snapshot-refetch doctrine backfill it (same shape as node.ratified; anchor is a rare deliberate act so the refetch cost is nil) (R5 SG2).
React Flow HAS real props for the gestures the pane-double-click lacked — `onNodeDoubleClick(_, node)`, `onPaneContextMenu(e)`, `onConnectStart/onConnectEnd` — so the SG2+IC rewire could DELETE the old DOM `onDoubleClick`+pane-class guard entirely; only the dead-drag still needs an event-target class check (R5 SG2/IC).
The dead-drag (drop-on-blank) is distinguished from drop-on-a-node by a `connectCompleted` ref set inside `onConnect`: RF fires onConnect (landed on a handle) AND onConnectEnd (always), so onConnectEnd fires the blank path only when NOT completed AND `event.target` is `.react-flow__pane` — the source node comes from a `connectSource` ref stashed in onConnectStart (R5 IC-b).
propose-batch takes per-item `author:"user"` but NOT a zone (BatchNodeInput has no zone field) — a human drag-connect batches into MAIN only, so gate the affordance OFF inside a zone (pass `onConnectToBlank={undefined}`) rather than silently escaping a sketch to main (placement-honesty; the single proposeAsUser path DOES tag activeZone, batch can't) (R5 IC-b).
Group-into-zone scopes to PENDING main-queue proposals only (zones hold proposals, never ratified nodes) — the synthetic-node-id-IS-proposal-id convention makes the selection filter a straight id-membership test over the inclusive store (`selectedPendingProposalIds`, pure+tested), and the affordance is main-board-only (a zone view's synthetics are already zoned) (R5 IC-c).
Playwright's `.click({button:"right"})` does NOT reliably fire React Flow's `onPaneContextMenu` — I had to `dispatchEvent(new MouseEvent("contextmenu", {clientX,clientY}))` on the pane to verify the modal opens; the handler is correct (a real user right-click works), it's an MCP/RF event-path quirk, so a gate drive uses an actual right-click, not the Playwright helper (R5 IC-a drive).

## Anti-patterns

Claiming a card from a board listing held in context — after the lead batch-adds, RE-PULL state and claim by id; a card remembered by title is not a card (mis-claimed t-806ff9da for t-9a4bd7b2).
Dropping Playwright/verification artifacts at the repo root — they default to CWD; move them to `.anthill/scratch/` immediately (the gate-safe home) and delete `.playwright-mcp/`.
Trusting a peer's land to be whole — untracked NEW files hide from pathspec commits (a skeleton commit shipped without its styles.css); check `git status` before building on it.
`setError`-ing the whole board on a peripheral fetch failure.
Leaving third-party chrome (React Flow controls, attribution, edge labels) at default styling — retune to tokens or the night palette breaks at the seams.
Waiting idle on a pending flag — the flag gates the land, not the work.
